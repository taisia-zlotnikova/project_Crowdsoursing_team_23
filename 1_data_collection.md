# Сбор датасета iNaturalist

## что имеем:
2 сущности:
- наблюдение
- фотография

одно наблюдение может содержать несколько фото

Для каждой финальной фотографии сохраняются:
- `photo_id`
- `observation_id`
- постоянная ссылка на наблюдение
- прямая HTTPS-ссылка на оригинал
- CC0-лицензия
- атрибуция
- таксон 
- хеш файла

## Что запрашиваем

Открытый метод [`GET /v1/observations`](https://api.inaturalist.org/v1/docs/#!/Observations/get_observations) без авторизации:

```text
https://api.inaturalist.org/v1/observations?taxon_id=47224&photos=true&photo_license=cc0&per_page=200&page=1
```

`47224` — Papilionoidea (бабочки). 

Параметры означают
- потомки указанного таксона
- только наблюдения с фото
- серверный фильтр CC0
- до 200 наблюдений на страницу 
- номер страницы. 

В ответе есть 
- `total_results`
- `page`
- `per_page`
- массив `results`

Нужные поля находятся в:
- `results[].photos[]`: 
    - `id`
    - `license_code`
    - `url`
    - `original_dimensions`
    - `attribution`
контекст и источник находятся в полях наблюдения `id`, `uri`, `taxon` и `user`.

Фильтр API не заменяет проверку в коде: скрипт ещё раз принимает только `photos[].license_code == "cc0"`. Указанная в наблюдении лицензия не используется как лицензия фото. Ссылка из `url` имеет вариант `/square.<extension>`; скрипт строит из неё прямую публичную ссылку S3 `/original.<extension>` согласно [iNaturalist Open Data](https://github.com/inaturalist/inaturalist-open-data).

(Официальная документация ограничивает API 100 запросами в минуту, рекомендует не превышать 60 в минуту и 10 000 в сутки. поэтому несколько страниц по 200 наблюдений)

## Согласованный набор кандидатов

Собираю 700 кандидатов: 
- 500 кандидатов-бабочек 
    - Papilionoidea
    - `taxon_id=47224`
- 200 кандидатов-негативов
    - 100 кандидатов Lepidoptera `taxon_id=47157` без Papilionoidea (`without_taxon_id=47224`)
    - 100 кандидатов цветковые растения Angiospermae `taxon_id=47125`

Фиксируем период наблюдения **с 2018-01-01 по 2026-11-09**
- убирает старые архивные снимки (есть за 20 век, как я понимаю. с другой стороны, мб, мы их тоже хотим)

Скрипт хранит:
- API-запрос
- фактическую дату наблюдения `observed_on` для каждой фотографии.
Если в заданном диапазоне какая-то группа не набрала нужное число фото, команда завершится с понятной ошибкой; тогда надо расширить даты.

## Запуск

Установка Pillow
```bash
python -m pip install -r requirements.txt
```

Сбор фото за определенные даты:
```bash
python scripts/inaturalist_dataset.py collect-plan --d1 2018-01-01 --d2 2026-11-09 --output-dir data/raw_candidates_2018_2026
```

Делаем html страничку со всеми фото:
```bash
python scripts/inaturalist_dataset.py gallery --input data/raw_candidates_2018_2026/all_candidates.jsonl --output data/candidates_gallery.html
```

Далее:
- Открыть `data/candidates_gallery.html` в браузере
- В заголовке каждой карточки есть группа, ID фотографии, ID наблюдения и таксон
- Нажатие на заголовок открывает наблюдение iNaturalist, на картинку — оригинальный файл.

## Проверка всех 700 фото:

Тут хочется проверить, что все фото доступны, открываются и скачиваются. Так-то проверять можно только итоговый выбор 400 кандидатов, но можно и все 700. 
Это достаточно небыстро (несколько минут точно)

```bash
python scripts/inaturalist_dataset.py validate-all \
  --input data/raw_candidates_2018_2026/all_candidates.jsonl \
  --output data/all_validated.jsonl \
  --report data/all_validation_report.json
```

Команда сохранит проверенные записи в `data/all_validated.jsonl`, а краткий итог — в `data/all_validation_report.json`. Можно также построить галерею из проверенного файла:

```bash
python scripts/inaturalist_dataset.py gallery --input data/all_validated.jsonl --output data/validated_gallery.html
```

### Что проверяет:

- `validate-all` проверяет все 700 кандидатов
    - скачивает **оригинал** по HTTPS
    - требует:
        - `Content-Type: image/*`
        - непустое тело
    - затем дважды открывает файл Pillow: 
        - `verify()` проверяет структуру
        - `load()` — что пиксели действительно декодируются.
В манифесте остаются HTTP-тип, число байтов, реальный формат и размеры; в отчёт попадает число ошибок. 
Прогресс печатается каждые 20 файлов. Ошибки загрузки не превращаются в отрицательные примеры.

Для моего прогона получилось:
```json
{
  "checked": 700,
  "download_or_decode_failed": 0,
  "byte_duplicates": 0
}
```
