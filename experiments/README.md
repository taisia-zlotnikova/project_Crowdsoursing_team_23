# OWLv2: влияние порога уверенности

## Гипотеза до запуска

Повышение порога уверенности с 0,1 до 0,2 и 0,3 уменьшит число ложных
обнаружений FP и повысит precision. Одновременно могут отсеиваться правильные
рамки: recall может снизиться, а FN — вырасти. Ожидаем, что до некоторого
порога сокращение FP перевесит рост FN и F1@IoU 0,5 увеличится. Предполагаем,
что среди трёх проверяемых значений наилучший F1 будет при пороге 0,3.
Это ожидание, а не заранее установленный результат или утверждение о глобальном оптимуме.

Гипотеза фиксируется до первого запуска 21 ноября 2026 года. Исходный протокол,
время его записи, контрольные суммы конфигураций, данных, весов и исходников
сохраняются в `owlv2_thresholds/pre_run.json`.

## Что меняется

Единственный изменяемый фактор — `models.owlv2.confidence`: 0,1 / 0,2 / 0,3.
Выполняются три независимых полных запуска модели, затем для каждого считаются
метрики. Повторная фильтрация готовых ответов вместо инференса не используется.

| Условие | Значение во всех трёх запусках |
| --- | --- |
| Модель | `google/owlv2-base-patch16-ensemble` |
| Revision весов и процессора | `cfd3195ba4ea9592eec887ded089f4c08eff231d` |
| Данные | `data/annotations.csv`, все 400 фотографий, 358 эталонных объектов |
| SHA-256 аннотаций | `efc87cc902b5492625821707e2f4062f1535e1190d6a0261a91088c1a250843a` |
| Текстовые запросы | `a photo of a butterfly`; `a photo of a moth` |
| Классы при оценке | Один общий целевой класс |
| Seed | 42 |
| Устройство | MPS, запуски последовательно на одном Mac |
| Веса | `float32`, `eval()`, `torch.inference_mode()` |
| NMS | Без разделения по классам, IoU = 0,5 |
| Порядок фотографий | Порядок строк CSV, без перемешивания и подвыборок |
| Повторные попытки | 0 |
| Сеть | Локальные веса и ранее скачанные оригиналы, без сетевых запросов |
| PyTorch / torchvision | 2.9.1 / 0.24.1 |
| Transformers | 4.57.6 |
| Pillow / huggingface-hub | 13.0.0 / 0.36.2 |

Изображение декодируется и переводится в RGB без поворота по EXIF. Процессор
`Owlv2ImageProcessorFast` из той же revision сначала умножает значения на 1/255,
затем дополняет изображение справа и снизу до квадрата (значение заполнения
0,5 в диапазоне [0, 1]), приводит к 960 × 960 пикселей с билинейной интерполяцией
(`resample=2`) и нормализует каналы. Mean: `[0.48145466, 0.4578275, 0.40821073]`,
std: `[0.26862954, 0.26130258, 0.27577711]`. Аугментаций нет.
Используются `Owlv2Processor` и `CLIPTokenizerFast`, максимальная длина
текстового входа — 16 токенов. `use_fast=True` фиксирован для всех вариантов.

Модель получает только изображение и два фиксированных текстовых запроса.
Категория источника, статус наличия бабочки и эталонные рамки ей не передаются.
Эталоны используются отдельно в `inference.evaluate` после сохранения предсказаний.

После предсказания процессор оставляет рамки с оценкой выше выбранного порога.
Координаты переводятся в систему исходного изображения, ограничиваются его
границами и нормализуются в `left`, `top`, `width`, `height` в диапазоне [0, 1].
Некорректные рамки отбрасываются. Затем применяется один и тот же NMS.

## Три запуска

Команды выполняются из корня проекта в окружении `.venv`. Для точного повторения
используются локально сохранённые веса и изображения. Если они ещё не скачаны,
предварительно выполните настройку из основного README; не меняйте изображения.

Порог 0,1:

```bash
.venv/bin/python -m inference.run --dataset data/annotations.csv --config inference/configs/owlv2_confidence_01.json --models owlv2 --output runs/owlv2-confidence-01 --device mps --local-files-only --offline-images
.venv/bin/python -m inference.evaluate --run runs/owlv2-confidence-01
```

Порог 0,2:

```bash
.venv/bin/python -m inference.run --dataset data/annotations.csv --config inference/configs/owlv2_confidence_02.json --models owlv2 --output runs/owlv2-confidence-02 --device mps --local-files-only --offline-images
.venv/bin/python -m inference.evaluate --run runs/owlv2-confidence-02
```

Порог 0,3:

```bash
.venv/bin/python -m inference.run --dataset data/annotations.csv --config inference/configs/owlv2_confidence_03.json --models owlv2 --output runs/owlv2-confidence-03 --device mps --local-files-only --offline-images
.venv/bin/python -m inference.evaluate --run runs/owlv2-confidence-03
```

Для продолжения прерванного совместимого запуска добавьте `--resume`. Для нового
независимого повтора задайте новую папку `--output`.

## Оценка и выбор конфигурации

Основная метрика — object F1 при IoU ≥ 0,5. На каждой фотографии используется
сопоставление с максимальным числом допустимых пар, каждая рамка участвует
максимум в одной паре. TP, FP и FN суммируются по всему набору до расчёта метрик.
Дополнительно считаются F1@0,75, precision, recall, ошибки на пустых фотографиях,
среднее, медиана и p95 времени. Правильные пустые ответы не добавляют TP.

Время включает подготовку входа, инференс и постобработку, с синхронизацией MPS.
Загрузка весов и чтение изображений измеряются отдельно. Первый вызов включён,
отдельного прогрева нет. Время фиксируется как характеристика этих запусков,
без вывода о влиянии порога на скорость по одному повтору.

Победитель среди трёх вариантов OWLv2 определяется по максимальному F1@0,5;
при равенстве можно предпочесть более быстрый. Это сравнение на данном наборе,
а не оценка качества на независимом тесте. Выбор итоговой модели проекта требует
сравнения победителя эксперимента с результатами остальных моделей на том же наборе.

## Артефакты

Каждая папка в `runs/` содержит `manifest.json`, конфигурацию внутри manifest,
ID всех изображений, версии библиотек и revision весов, контрольные суммы кода,
`owlv2/predictions.jsonl`, `diagnostics.jsonl`, `run_summary.json`, `metrics.json`
и `comparison.csv`. В диагностике фиксируются хеш каждого исходного изображения,
его размеры, оценки рамок и время обработки.

В `experiments/owlv2_thresholds/` сохраняются протокол до запуска и компактные
итоговые отчёты для просмотра результатов без повторного инференса.

## Результаты

Все три запуска завершились: 400 из 400 фотографий, `scope=full`, технических
ошибок — 0. Каждый вариант выполнен одним отдельным полным запуском, с одной
попыткой на фотографию. Гипотеза записана в 08:43:02 UTC 21 ноября 2026 года,
первый инференс начался в 08:43:16 UTC.

| Порог confidence | F1@0,5 | Precision@0,5 | Recall@0,5 | TP | FP | FN | Рамок выдано | F1@0,75 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0,1 | 0,6516 | 0,4915 | 0,9665 | 346 | 358 | 12 | 704 | 0,4595 |
| 0,2 | 0,8437 | 0,7589 | 0,9497 | 340 | 108 | 18 | 448 | 0,6005 |
| **0,3** | **0,8981** | **0,8634** | **0,9358** | **335** | **53** | **23** | **388** | **0,6408** |

Precision и recall рассчитываются по объектам, а не по фотографиям. Во всех
вариантах `TP + FN = 358` эталонных объектов. `TP + FP` — число предсказанных рамок.

| Порог | Пустых фото с ложными находками / 46 | FP на пустых фото | Среднее, с/фото | Медиана, с/фото | p95, с/фото |
| --- | --- | --- | --- | --- | --- |
| 0,1 | 16 / 46 | 20 | 0,2975 | 0,3016 | 0,3148 |
| 0,2 | 9 / 46 | 9 | 0,2980 | 0,3024 | 0,3160 |
| 0,3 | 8 / 46 | 8 | 0,2965 | 0,2999 | 0,3129 |

Среднее время осталось около 0,30 с/фото. Различия между этими одиночными
запусками малы и не доказывают ускорения от изменения порога.

### Что наблюдаем и почему

Предположение о пороге 0,3 подтвердилось **среди трёх проверенных значений**.
От 0,1 до 0,3 F1@0,5 вырос с 0,6516 до 0,8981, на 24,65 процентного пункта.
FP сократились на 305 рамок, с 358 до 53. Одновременно потеряно 11 правильных
находок: TP уменьшились с 346 до 335, а FN выросли с 12 до 23.

При переходе 0,1 → 0,2 модель потеряла 6 правильных находок и убрала 250 FP.
При переходе 0,2 → 0,3 потеряла ещё 5 правильных находок и убрала ещё 55 FP.
В обоих случаях сокращение ложных обнаружений перевесило потерю правильных.
Поэтому precision существенно вырос, recall немного снизился, а F1 вырос.

Объяснение согласуется с механизмом порога: он отсекает слабые предсказания.
В этих запусках удалённые рамки чаще оказывались лишними, чем правильными
при сопоставлении с эталоном. Это не изменение весов модели и не улучшение
координат оставшихся рамок. Порог не различает причины FP: дубли, ошибочные
объекты и рамки с недостаточным IoU могут иметь низкую оценку.

Максимум при 0,3 не означает, что это глобально оптимальный порог. Значения
выше 0,3 не проверялись, а дальнейшее повышение может увеличить число пропусков
и ухудшить F1. Результат относится к этому размеченному набору.

### Выбранные настройки

Для **OWLv2 выбираем confidence = 0,3**, NMS IoU = 0,5, оба исходных запроса
и остальные настройки без изменений: [конфигурация](../inference/configs/owlv2_confidence_03.json).
Приоритет скорости не понадобился: F1 трёх вариантов различается.

Эта оценка взята из ранее выполненного полного запуска
`runs/qwen-maxpixels-1048576` и не является четвёртым запуском данного эксперимента.
Сверены SHA-256 аннотаций и каждого изображения, порядок ID, версии библиотек,
устройство и контрольные суммы реализации. Происхождение сохранено в `results.json`.
