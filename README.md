# Crowdsourcing project · Team 23

Проект команды 23: сбор фотографий, разметка взрослых бабочек, независимый REVIEW
и оценка Grounding DINO, OWLv2 и Qwen3-VL. Репозиторий содержит воспроизводимый
экспорт эталонной разметки, локальный инференс, сравнение экспериментов и дашборд.
Обучение моделей не выполняется.

## Установка

Требуется Python 3.13. Все команды выполняются из корня репозитория.

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Для работы с ноутбуками разметки установите дополнительные зависимости
в то же окружение:

```bash
.venv/bin/python -m pip install -r clean_annotation/requirements.txt
.venv/bin/jupyter lab
```

Сам API-код разметки и экспортёр используют стандартную библиотеку Python.
[Инструкция разметки](clean_annotation/README.md) описывает настройку проектов,
независимый REVIEW, переразметку и подготовку материалов.

Модели и процессоры загружаются из Hugging Face с закреплёнными ревизиями.
Веса сохраняются в стандартном кеше Hugging Face, изображения — в `data/images/`.
Окружение, кеш изображений и результаты запусков исключены из Git.

## Входные данные для инференса

Эталон опубликован в [exports/final_butterflies_v1/](exports/final_butterflies_v1/).
`data/annotations.csv` — его побайтно идентичная копия для команд инференса:
400 размеченных фотографий, 358 эталонных рамок и 46 изображений без целевых объектов. Объекты — взрослые дневные и ночные
бабочки; гусеницы, куколки и другие насекомые не входят в целевой класс.

CSV содержит `photo_id`, `image_url`, размеры изображения, статус и рамки
в поле `boxes_normalized_xywh`. Каждая рамка имеет вид
`[left, top, width, height]`, координаты нормализованы в диапазон от 0 до 1.

Для инференса без эталона достаточно CSV или JSONL с `photo_id` и ссылкой
в поле `image_url` или `photo_url`:

```json
{"photo_id":18821,"photo_url":"https://inaturalist-open-data.s3.amazonaws.com/photos/18821/original.jpg"}
```

Модель получает исходное RGB-изображение и фиксированный текстовый запрос.
Эталонные рамки, статус и категория фотографии в модель не передаются.
Эталон используется при расчёте метрик и отрисовке результатов.

## Инференс и оценка

Запуск трёх моделей на размеченном датасете:

```bash
.venv/bin/python -m inference.run --dataset data/annotations.csv --models all --output runs/baseline --device auto
.venv/bin/python -m inference.evaluate --run runs/baseline
```

Модели обрабатывают один и тот же набор изображений последовательно.
`--device auto` выбирает MPS, CUDA или CPU в зависимости от доступности.
Устройство можно указать явно: `--device mps`, `--device cuda`, `--device cpu`.

Основные параметры запуска:

| Параметр | Назначение |
| --- | --- |
| `--models` | `all` или список из `grounding-dino`, `owlv2`, `qwen3-vl` |
| `--config` | JSON-конфигурация; по умолчанию `inference/configs/baseline.json` |
| `--output` | Папка результатов эксперимента |
| `--limit N` | Первые N фотографий для пробного запуска |
| `--photo-ids ID ...` | Конкретные фотографии; используется вместо `--limit` |
| `--resume` | Продолжить запуск, пропустив сохранённые успешные ответы |
| `--retries N` | Количество дополнительных попыток на фотографию; по умолчанию 0 |
| `--local-files-only` | Использовать только заранее загруженные веса |
| `--offline-images` | Читать изображения только из проверенного локального кеша |

Предсказания сохраняются после каждой фотографии. Для продолжения запуска
повторите исходную команду с `--resume`, сохранив датасет, конфигурацию, код
инференса, версии библиотек и устройство. Для независимого прохода укажите
новую папку `--output`. После завершения инференса выполните `inference.evaluate`.

## Формат результатов

```text
runs/<эксперимент>/
  manifest.json
  comparison.csv
  <модель>/
    predictions.jsonl
    diagnostics.jsonl
    run_summary.json
    metrics.json
```

`predictions.jsonl` содержит одну запись на фотографию:

```json
{"photo_id":19297850,"boxes":[{"left":0.1,"top":0.2,"width":0.3,"height":0.4}],"error":null}
{"photo_id":28485219,"boxes":[],"error":null}
```

Координаты относятся к исходному изображению. Пустая успешная детекция —
`boxes=[]`; техническая ошибка — `boxes=null` с описанием в `error`.

`manifest.json` фиксирует датасет, выбранные ID, промпты, параметры, ревизии
весов, версии библиотек, устройство и контрольные суммы кода.
`diagnostics.jsonl` содержит ответы моделей, scores детекторов, историю попыток
и длительности. `run_summary.json` сохраняет сведения о сессиях и загрузке модели.
`metrics.json` содержит общие и поизображенные метрики; `comparison.csv` —
сводную таблицу моделей.

## Метрики

Для каждого изображения строится максимальное паросочетание предсказанных
и эталонных рамок при IoU ≥ 0.5 и отдельно при IoU ≥ 0.75.
Каждая рамка участвует максимум в одной паре.

```text
IoU = площадь пересечения / площадь объединения
TP = количество сопоставленных пар
FP = количество предсказанных рамок − TP
FN = количество эталонных рамок − TP

Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2TP / (2TP + FP + FN)
```

TP, FP и FN суммируются по всем фотографиям до расчёта Precision, Recall и F1.
При нулевом знаменателе соответствующая метрика равна 0. Корректная пустая
фотография не добавляет TP; лишние рамки на ней учитываются как FP.

Дополнительно рассчитываются:

- число лишних рамок на пустых фотографиях;
- число и доля пустых фотографий с ложными находками;
- показатели групп с 0, 1 и несколькими эталонными объектами;
- количество ошибок детекции FP+FN и технических ошибок;
- среднее, медиана и p95 времени обработки изображения.

Время обработки включает подготовку входа, модель и постобработку. Получение
изображений и загрузка весов измеряются отдельно. На MPS/CUDA используется
синхронизация перед остановкой таймера. Первый вызов включается в измерение;
сравниваемые запуски следует выполнять в одинаковых условиях.

При технических ошибках запуск имеет статус `incomplete`, а общая оценка
`quality=null`. Частичные выборки отмечаются `scope=subset`.
Основная метрика выбора модели — F1@IoU=0.5; при равенстве учитывается скорость.

## Абляция Qwen: разрешение изображения

Эксперимент изменяет только `max_pixels`: с 262144 до 1048576.
Промпт, `min_pixels`, длина ответа, seed и веса остаются одинаковыми.
Параметры находятся в `inference/configs/qwen_maxpixels_1048576.json`.

Гипотеза: увеличение разрешения входа повысит точность границ и F1@IoU=0.75,
увеличив время обработки. Для проверки используется весь размеченный набор
из 400 фотографий. Baseline и эксперимент выполняются на одном устройстве.

```bash
.venv/bin/python -m inference.run --dataset data/annotations.csv --config inference/configs/qwen_maxpixels_1048576.json --models qwen3-vl --output runs/qwen-maxpixels-1048576 --device auto --resume
```

`--resume` создаёт новый запуск, если папки результатов ещё нет, либо продолжает
совместимый запуск и пропускает сохранённые успешные ответы. Для независимого
повтора укажите новую папку `--output`.

После успешного завершения инференса рассчитайте метрики:

```bash
.venv/bin/python -m inference.evaluate --run runs/qwen-maxpixels-1048576
```

В дашборде выберите
эксперимент `qwen-maxpixels-1048576`, откройте вкладку «Эксперименты» и сравните
с `baseline`. Сравниваются F1@0.5, F1@0.75, Precision, Recall, TP/FP/FN,
ложные находки на пустых фото и время обработки.

[Протокол эксперимента](experiments/qwen_resolution.md).

## Дашборд

После расчёта метрик запустите приложение:

```bash
.venv/bin/python -m streamlit run dashboard/app.py --server.address 127.0.0.1 --server.port 8502 --server.headless true --browser.gatherUsageStats false
```

Откройте <http://127.0.0.1:8502> и выберите эксперимент в боковой панели.
Доступны четыре вкладки:

- **Модели** — таблица метрик, график качества, конфигурация и экспорт CSV.
- **Фотографии** — эталонные и предсказанные рамки, фильтры FP/FN и ответы модели.
- **Группы** — результаты по числу объектов и ложным находкам на пустых фото.
- **Эксперименты** — сравнение настроек и разницы показателей.

Дашборд читает сохранённые результаты и локальный кеш изображений.
Кнопка «Обновить результаты» перечитывает отчёты. Для сравнения экспериментов
нужны одинаковые аннотации и наборы фотографий. Папка результатов настраивается
в боковой панели; порт сервера задаётся через `--server.port`.

## Визуализация случайной выборки

Сохранение пяти случайных фотографий с рамками выбранной модели:

```bash
.venv/bin/python -m inference.visualize --run runs/baseline --model qwen3-vl
```

Количество фотографий и воспроизводимая выборка:

```bash
.venv/bin/python -m inference.visualize --run runs/baseline --model grounding-dino --n 10 --seed 42
```

Зелёные рамки обозначают эталон, красные — предсказания.
Одинаковый `--seed` выбирает одинаковые фотографии у разных моделей одного
запуска. Без `--seed` выборка случайная при каждом вызове.

Результаты сохраняются в
`runs/<эксперимент>/<модель>/visualizations/<время>/`: отдельные PNG,
общая картинка `contact_sheet.png` и `sample.json` с ID и рамками.
`--output` задаёт другую пустую папку, `--max-size` — максимальную сторону
фотографии в PNG (по умолчанию 1200). Модели повторно не запускаются.
